# Принятые решения

## Модель данных

### 1. Поля угрозы

| Поле | Почему |
|---|---|
| `zone` | Цветовые зоны как в Kaspersky OpenTIP: вредоносный ли объект. По умолчанию `grey`, данных нет |
| `severity` | Насколько опасно. `unknown` значит «не оценено», для `green` и `grey` другое значение недопустимо |
| `types` | Массив, потому что один образец часто относится к нескольким категориям. Словарь исключает разнобой вроде `Trojan` и `trojan` |
| `first_seen_at`, `last_seen_at`, `file_size`, `sha1`, `sha256` | Помогают сопоставлять данные из разных источников |
| `tlp` | Стандартная метка распространения. По умолчанию `amber`, так безопаснее, если автор ничего не указал |
| `confidence` | Уверенность автора, 0-100, как в STIX 2.1 |
| `revoked` | Ложные срабатывания отзывают, а не удаляют |
| `created_by`, `updated_by` | Заполняет сервер по ключу, клиент не может их подделать |

### 2. Совместимость с заданием

Обязательными остались только `md5` и `name`. Защита добавляет к контракту TLS, заголовок
`X-API-Key` и запрет лишних полей.

### 3. `PUT` как полная замена

Так написано в задании и соответствует семантике HTTP. MD5 берётся из адреса, в теле он
запрещён, чтобы не было двух значений.

### 4. Текстовые столбцы с `CHECK` вместо `ENUM`

Значения проще менять миграцией, а неизвестное значение БД всё равно не примет.

### 5. Уникальность только у SHA-256

У одного файла один MD5, поэтому два MD5 с одним SHA-256 означают ошибку в данных (`409`). Для
SHA-1 уникальности нет: известны разные файлы с одинаковым SHA-1 (SHAttered). Коллизии MD5 тоже
существуют, но ключ по MD5 задан заданием, а различить такие файлы помогает `sha256`.

### 6. История в триггере

Триггер записывает каждую версию в `threat_history`, поэтому история полна даже при изменениях
в обход сервиса. Отдельного эндпоинта нет, для аудита хватает таблицы.

### 7. Одна общая запись на MD5

В задании MD5 уникален, а `PUT` заменяет данные. Поэтому запись может менять любой `writer`:
иначе вторая организация вообще не смогла бы передать свои данные.

Запись, которую последним менял другой ключ, можно заменить только с конкретной версией в
`If-Match` (`428`): организация обязана сначала прочитать чужие данные. 

**Нерешённый риск:** партнёр может сменить `red` на `green`. История покажет, кто это сделал, но
не предотвратит подмену.

**Следующий шаг:** отдельный отчёт от каждой организации, а `GET` возвращает сводку. Это закрывает
риск, но меняет смысл `409` и требует правил слияния при разногласиях, поэтому не реализовано.

## API

### 8. Спецификация как источник правды

`oapi-codegen` генерирует интерфейс, который разрешает только объявленные ответы. Тот же файл
использует валидатор запросов, а CI проверяет, что сгенерированный код не устарел.

### 9. Swagger отдельно и только для чтения

В отдельном контейнере он не добавляет файлы и исключения из защиты в сервис. Отправка запросов
отключена, потому что для неё API пришлось бы разрешить CORS, а браузеру довериться dev-CA.
Сценарии можно проверить через коллекцию Postman или запросами.

## Хранение

### 10. pgx и SQL вместо ORM

Запросов всего четыре, и ORM только добавила бы сложности. SQL проверяют интеграционные тесты на
реальном PostgreSQL. Если запросов станет много, можно перейти на `sqlc`.

### 11. Миграции внутри бинарника

Схема версионируется вместе с кодом, отдельный инструмент в образе не нужен. В compose миграции
запускаются отдельным сервисом.

### 12. Отдельная роль сервиса в БД

Миграции работают под владельцем схемы, а сервис под ролью `threats_app`, которая не может удалить
таблицу или переписать историю. Права выдаёт миграция, если такая роль существует.

## Разработка

### 13. Временная база на каждый тест

Тесты параллельны и независимы, а для запуска нужен только `TEST_DB_URL`. testcontainers-go дал бы
то же самое, но добавил бы Docker SDK в зависимости.

### 14. Настройки из окружения, секреты из файлов

Один образ для всех сред, а `*_FILE` позволяет не держать секреты в переменных. Настройки
проверяются при старте, все ошибки выводятся сразу.

### 15. Инструменты в отдельном модуле

`tools/go.mod` фиксирует версию `oapi-codegen` и не добавляет её в зависимости сервиса.
