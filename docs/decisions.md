# Принятые решения

Короткие записи в духе ADR: что решили и почему.

## 1. Модель угрозы ориентирована на Kaspersky OpenTIP

- **`zone`** (`red/orange/yellow/green/grey`) — как цветовые зоны Kaspersky
  Threat Intelligence Portal. Отвечает на вопрос «вредоносный ли объект».
  По умолчанию `grey` — «данных недостаточно».
- **`severity`** — отдельный вопрос «насколько опасно». Значение `unknown`
  честно означает «не оценено» вместо угаданного уровня. Чтобы данные не
  противоречили друг другу, для `green`/`grey` допустимо только `unknown`.
- **`types`** — массив из словаря, построенного по части `Behaviour` в именах
  Kaspersky (`Trojan.Win32…`, `Backdoor.Linux…`). Массив, потому что в обмене
  между организациями один образец часто описывают несколькими категориями;
  фиксированный словарь — чтобы не было разнобоя `Trojan`/`trojan`/`trojan-horse`;
  `other` закрывает редкие случаи.
- **`first_seen_at`/`last_seen_at`, `file_size`, `sha1`/`sha256`** — есть в
  OpenTIP и полезны для сопоставления данных из разных источников.
- **`revoked`** — ложные срабатывания отзывают, а не удаляют, сохраняя историю.
- **`created_by`/`updated_by`** заполняет сервер по API-ключу — аудит,
  который клиент не может подделать.
- **`platform` не вводилась**: платформа уже есть в имени угрозы — два места
  для одного факта ведут к противоречиям.
- **Имя не проверяется по формату Kaspersky**: в обмене встречаются имена других
  вендоров; запрещены только пробелы по краям и управляющие символы.

## 2. Совместимость с исходным контрактом

Обязательными остались только `md5` и `name`, как в задании. Клиент, написанный
строго по исходной спецификации, продолжает работать; новые поля получают
значения по умолчанию.

## 3. `PUT` — полная замена, MD5 из пути

По семантике HTTP и описанию в задании («заменяет информацию»). MD5 в теле
`PUT` отклоняется (`additionalProperties: false`), чтобы не было двусмысленности
«какой MD5 правильный».

## 4. Оптимистичная блокировка через ETag/If-Match

Защищает от «потерянного обновления», когда два аналитика правят одну запись.
Для клиентов, не передающих `If-Match`, поведение не меняется.

Значение `ETag` берётся из столбца `version`: `UPDATE … WHERE version = $v`
атомарно проверяет его при записи. В теле ответа версии нет: она дублировала бы
заголовок, а двум источникам одного значения незачем существовать.

## 5. Спецификация — единственный источник правды

`oapi-codegen` генерирует strict-интерфейс: обработчик может вернуть только
объявленные в спецификации ответы, иначе код не скомпилируется. Тот же файл,
встроенный в бинарник, использует валидатор kin-openapi. CI проверяет, что
сгенерированный код не устарел (`make check-generate`).

## 6. pgx и рукописный SQL вместо ORM

Запросов три, они статические и параметризованные; ORM добавила бы сложность
без пользы. Изначально планировался `sqlc` (генерация кода из SQL), но в среде
разработки его не удалось собрать; репозиторий покрыт интеграционными тестами
на реальном PostgreSQL, включая проверку ограничений схемы. Переход на sqlc —
механическая замена одного файла.

## 7. Миграции goose, встроенные в бинарник

Схема версионируется вместе с кодом, отдельный инструмент в образе не нужен.
Advisory lock делает запуск безопасным для нескольких реплик. В compose
миграции — отдельный одноразовый сервис, а не шаг старта приложения.

## 8. Текстовые столбцы с `CHECK` вместо `ENUM` PostgreSQL

Значения перечислений проще менять миграцией (`ALTER TABLE … CHECK`), чем
`ALTER TYPE`; при этом БД по-прежнему не примет неизвестное значение.

## 9. API-ключи, а не JWT/OAuth

См. [security.md](security.md#аутентификация).

## 10. Интеграционные тесты на отдельных временных базах

Каждый тест создаёт базу `tx_test_<random>`, мигрирует и удаляет её. Тесты
параллельны и независимы, а для запуска нужен только адрес PostgreSQL
(`TEST_DB_URL`): в CI — service container, локально — `docker compose up db`.
Альтернатива — testcontainers-go — даёт то же, но тянет Docker SDK в
зависимости проекта.

## 11. Конфигурация из окружения, секреты из файлов

12-factor: один образ для всех сред. `*_FILE` позволяет не держать секреты в
переменных окружения. Конфигурация валидируется целиком при старте, все
ошибки выводятся сразу.

## 12. Инструменты разработки в отдельном модуле

`tools/go.mod` фиксирует версию oapi-codegen (`go tool -modfile=tools/go.mod`)
и не засоряет зависимости основного модуля.
